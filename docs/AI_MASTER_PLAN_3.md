Scope & Dual-Mode ExecutionEpoch 3 implements a single user-facing entry point: disktracker ask "<question>". The agent acts as an advanced natural-language orchestration layer over a local SQLite knowledge graph and the underlying operating system.Operational ModesExploratory Mode (Default): Read-only execution. The agent is restricted to non-mutating query tools (Read-only Text-to-SQL, external signatures, whitelisted read-only CLI commands).Action Mode (Gated via --interactive / -i): Read-write execution. The agent can invoke mutating state changes (e.g., executing OS-level deletion commands, managing snapshots). Every mutating tool call triggers a strict, non-bypassable Human-in-the-Loop (HITL) interrupt at the graph level.Session Persistence: The agent supports multi-turn conversations across separate CLI invocations using thread checkpointing, allowing users to recall context or continue investigations across multiple terminal sessions.1. The Daemon: ETW & The Relational Knowledge GraphBefore the agent can reason about the disk, the underlying data layer must track both installation and runtime behavior. The Rust daemon integrates Event Tracing for Windows (ETW) to capture dynamic system events, bridging the gap between static OS states and dynamic app behavior.Install-Time Process Tree Correlation: The daemon monitors ETW for process creation, file writes, and registry modifications. When an installer process (e.g., msiexec.exe or setup.exe) writes a block of files and subsequently writes an Uninstall string to the Windows Registry, the daemon correlates the Process ID (PID) to retroactively map all files written during that session to the installed application.Active Runtime Tracking: The daemon also listens for runtime file handle creations. When a known executable (e.g., hollow_knight.exe) dynamically generates cache folders or log files in arbitrary locations (like AppData\LocalLow), the daemon captures this relationship.Relational Mapping: Both Install-Time and Runtime events are committed to local SQLite tables (e.g., app_install_footprints and app_runtime_artifacts). This transforms the database from a flat file index into a relational knowledge graph, allowing the AI to instantly query exactly what an app installed and what it generated afterward.2. Tool Schema MatrixThe rigid JSON-RPC methods from Epoch 2 are replaced by a highly dynamic toolset. The agent leverages its understanding of relational algebra to construct its own queries on the fly.Read-Only Tools (Available to All Modes)Tool NameScope & Safety Mechanicssqlite_read_queryThe Core Engine. The agent is injected with the database schema (ETW events, snapshots, file states, registry uninstalls). It synthesizes exact SELECT queries utilizing complex JOINs to bridge registry data with dynamic paths. Safety Invariant: The daemon executes this query via a connection opened explicitly with SQLITE_OPEN_READONLY. Any structural mutation (INSERT, UPDATE, DELETE, DROP) is rejected natively by the SQLite database engine.fetch_signatureExternal Context. Accepts a generic folder name or executable hash. Pings a community-driven remote API (or local JSON signature file) to retrieve human-readable context (e.g., "GLCache is an NVIDIA shader cache; safe to delete").cli_read_commandOS Interrogation (Context-Aware). Executes safe, passive system commands. Dynamic Shell Detection: The system detects whether the user is executing DiskTracker inside cmd.exe or powershell.exe and injects this context into the LLM system prompt. The agent can use any read-only command valid for that specific shell (e.g., Get-ItemProperty for PS, dir for CMD) to gather live context not yet committed to the database. Checked against a strict execution whitelist within the daemon to prevent silent mutation (e.g. > redirects or pipeline mutations).Mutating Tools (Gated Behind Action Mode + HITL)Tool NameScope & Safety Mechanicscli_write_commandOS Execution. Allows the agent to construct commands that modify the filesystem (e.g., Remove-Item, del). Triggers an immediate HITL pause, presenting the raw string command to the user for terminal approval before execution.snapshot_manageState Mutator. Direct API call via JSON-RPC to delete or compress historical DiskTracker snapshots. Triggers an immediate HITL pause.3. Runtime Decision: Pure Rust Graph ExecutionThe orchestration engine lives entirely inside the crates/agent workspace, utilizing the rust-langgraph library (crates.io, feature-gated).[dependencies]
rust-langgraph = { version = "0.1", features = ["openai", "prebuilt", "sqlite-checkpoint"] }
Pre-Flight Initialization: Before the Pregel state graph can execute, the disktracker ask command must load the local configuration (base-url, api-key, and model-name). These values are passed directly into the rust-langgraph configuration struct (e.g., configuring the reqwest client inside the openai adapter). If any parameter is missing, execution is halted immediately before the graph is constructed.The agent never accesses the Daemon's core SQLite database directly for reading/writing graphs, nor does it spawn OS shells natively. All OS and Disk state tool calls route through structured JSON-RPC over the local named pipe (\\.\pipe\disktracker).4. Graph State and Human-in-the-Loop ArchitectureTo safely support cli_write_command, snapshot_manage, and cross-CLI conversational memory, the directed state graph relies on a checkpointer.#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct AskState {
    pub question: String,
    pub tool_calls: Vec<ToolCallRecord>,
    pub round_count: u32,
    pub interaction_approved: Option<bool>,
    pub final_answer: Option<String>,
}
Directed Execution Flowplan_node: The LLM generates a tool request (e.g., a SQL query or a destructive OS command).Conditional Routing Edge:If sqlite_read_query, fetch_signature, or cli_read_command → Route directly to tool_exec.If cli_write_command or snapshot_manage → Route immediately to human_interrupt_node.If round_count >= 6 → Route directly to END.human_interrupt_node: Saves the graph state using the checkpointer. The CLI blocks on standard input and prompts the operator:⚠️ Agent requested execution of a destructive command:
Tool: cli_write_command
Command: powershell -Command "Remove-Item -Recurse 'C:\Users\you\AppData\LocalLow\Team Cherry'"

Do you authorize this action? [y/N]: 
Resumption: If the user types y/yes, the checkpoint resumes execution into tool_exec. If denied, an "Action Aborted by User" error payload is injected back into the state, allowing the LLM to synthesize a graceful confirmation of cancellation and halt.5. 6. Session & Context ManagementBy default, every invocation of disktracker ask is ephemeral. When the command finishes, the thread context is wiped. However, DiskTracker supports multi-turn memory using LangGraph's persistent state checkpointing (backed by an isolated agent_sessions.db file, separate from the Daemon's core disk database).Global ConfigurationUsers can set DiskTracker to record all chat sessions by default:disktracker ai config --chat-session-store true
(Default is false to prevent unbounded growth of LLM context histories).CLI Invocation FlagsIf global storage is false, users can explicitly save a specific context thread:disktracker ask --store-this-session "Where did Steam install my latest game?"
Output will append: [Session ID: a1b2c3d4 saved. Use --session a1b2c3d4 to continue.]Session Recall & ManagementUsers can view, resume, or export past investigation threads:List Active Sessions: disktracker ai session list (Returns IDs, timestamps, and the first question).Resume Conversation: disktracker ask --session a1b2c3d4 "Can you delete the logs you just found?" (Loads the checkpoint state so the LLM remembers the paths it found in the previous command).View Full Transcript: disktracker ai session show a1b2c3d4 (Prints the entire history of the session without querying the LLM).7. Engine Injection: When disktracker ask is called, the system extracts the api-key, base-url, and model-name to instantiate the underlying OpenAI-compatible adapter for rust-langgraph. If the handshake fails, the CLI intercepts and outputs the raw upstream response payload (e.g., specific HTTP error payloads).8.
